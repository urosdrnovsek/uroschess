# Responsive startup — 12 October 2026

Launching from the menu created a window before the complete lesson library
had been parsed and validated. This work ran on the GUI thread, which did not
service window events until it finished. The reported window eventually opened;
this was a startup delay rather than a confirmed crash.

SAN resolution formatted every legal move, including unrelated pieces and
squares, while importing each recorded move. Formatting SAN itself generates
legal continuations and checks disambiguation. Filtering legal candidates by
piece, destination and promotion before comparing canonical SAN removes this
repeated work. Castling, captures, en passant, promotion and file/rank
ambiguity still go through legal-move and canonical-notation checks.

Content preparation now runs on a background thread. The main thread displays
Preparing lessons, services resize and close events, and receives the library
or loading error through a queue. No Pygame rendering or local progress database
access happens in the loading worker. Closing during startup returns without
waiting for content preparation; the worker is a daemon and only reads bundled
resources.

A fresh content load took 0.897 seconds in the local probe, with all 33 lessons
and no content errors. Constructing and drawing a fresh headless app took
2.096 seconds. These timings describe this runtime, not a cross-platform target.
The focused startup, engine, PGN-import and lesson checks passed 43 tests;
content validation and rendering smoke passed. Regression checks cover window
resize/close during a blocked load, loading errors, canonical special moves,
ambiguity rejection, and avoiding notation generation for unrelated moves.

The full suite passed all 180 tests on Python 3.14.7 / Pygame 2.6.1.
