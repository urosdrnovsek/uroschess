# Desktop update and usability review — 29 October 2026

This completes the local work following `f38fd8f`. The starter pack now has
47 games, 47 lessons and 16 published courses.

## Completed work

- Fourteen lessons, each with a guided and independent exercise, across seven
  courses: escaping check, castling with either colour, rook tactics, en passant
  and Black promotion, protecting threatened pieces, kings/rooks helping pawns,
  and active rooks. Their 28 exercises include hints and reviewed alternatives.
  Guide descriptions and the README match the expanded content.
- Responsive startup with a loading screen, resize/close handling and background
  content preparation. SAN import filters legal candidates before formatting
  notation, retaining canonical resolution for special moves and ambiguity.
- Ordinary play shows game mode, human colour and difficulty. Controls use
  clearer labels and a consistent bottom-right Main menu exit, including during
  search and promotion. Unavailable takeback/import controls are disabled and
  skipped by keyboard focus; leaving cancels search and clears temporary input.
- A supported window minimum replaces the unusable 360×320 claim: 360×720 for
  widths below 720, or 720×600 for wider windows. Both startup and normal resize
  use the same rule. The default window remains 980×760.
- Compact lesson/replay layouts omit the top portrait below 820 pixels high,
  preserve board space, and give larger text more reading room. The longest
  questions retain at least 40 pixels of scrollable feedback in the audit.
  Board coordinate labels fit inside their frame instead of touching the status.
- Secondary text is adjusted for at least 4.5:1 contrast on the app's relevant
  surfaces in representative light/dark palette checks. This addresses faint
  instructions and labels; it is not a general accessibility certification.
- Refreshed README screenshots, current handoff notes, a repeatable usability
  audit command and a browser feasibility assessment.

The audit uses only an in-memory progress database. It visits every lesson step,
all three text sizes, seven resize requests (including rejected undersized
requests), all guide/course/library pages, medals, challenge selection, ordinary
play, challenge play and replay. Seven representative lessons also exercise
hint, reveal, exploration, return, restart, completion and authored wrong moves.
It writes captures and a machine-readable report under the selected output
folder. The report records requested and actual window sizes separately.

The new content regressions complete/resume all fourteen lessons and check
actual board claims: check removal, castling both pieces, skewer captures,
back-rank mate, en passant expiration, Black promotion, safe escape squares,
pawn support and rook coordination. Existing tests cover progress, assistance,
Monty's entitlement, challenge recovery, stale searches and input navigation.

The installed wheel is checked outside the checkout, using a temporary virtual
environment, the already installed Pygame runtime and no runtime downloads.
Build tooling is supplied from the machine's existing setuptools installation.
The check asserts that the imported package comes from the installed wheel,
resolves every lesson, renders menu/lesson/replay screens, resumes a challenge
and loads all seven packaged portraits.

## Practical limits and next work

This is an internal code, rendering and interaction audit. No child/adult
learner observation was conducted, and no physical touch device, screen reader,
Windows/macOS installation or other Python interpreter was tested locally.
The CI matrix remains configured for Python 3.9, 3.12 and 3.13.

The supported minimum is a desktop constraint; it is not a responsive phone
layout. Replay notes still show a short excerpt in compact views, and canvas
text has no native screen-reader semantics. Learner sessions, broader opponent
calibration and further accessibility work remain open.

See [the browser feasibility assessment](web-feasibility-2026-10-29.md) for
reuse, runtime blockers, estimates and prototype acceptance checks. No browser
build or public website is part of this desktop update.
